# Docs Plugin API Contract (M2 / M2b)

Every Rookery RPC method, SDK facility, manifest contribution type, and collection/document feature that `crow/plugins/docs` uses, marked **exists in Rookery now** or **needed (M2 / M2b)**.

Client API adapters and M2b bridge types live in [`src/types.ts`](./src/types.ts) and [`src/views/api.ts`](./src/views/api.ts); host-half handlers, commands, tools, and the `docs` service live in [`src/host.ts`](./src/host.ts); plugin interface schemas live in [`interface.ts`](./interface.ts) and [`plugin.json`](./plugin.json).

## 3. Plugin Host RPC Methods (`plugins.rpc` to `"docs"`)

All invoked via `rookery.host.call` from the client half; execution requires **M2 (extension host)** and **M2b (`data.*`, `documents`, `entities`)**:

| Method           | Params                                                                | Result                             | Required access                           |
| ---------------- | --------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------- |
| `create`         | `{ title?, parent?, space?, index?, template?, markdown?, private? }` | `{ id, spaceId, document, title }` | `use` on `pages`                          |
| `document`       | `{ id, space? }`                                                      | `{ id }`                           | `view` on page (+ creates doc if missing) |
| `move`           | `{ id, parent, index?, space? }`                                      | `{ id, parent, rank }`             | `use` on `pages` (cycle-checked)          |
| `trash`          | `{ id, space? }`                                                      | `{ trashed }`                      | `use` on subtree                          |
| `restore`        | `{ id, space? }`                                                      | `{ restored }`                     | `use` on subtree                          |
| `purge`          | `{ id, space? }`                                                      | `{ purged }`                       | `use` on subtree (deletes Yjs docs too)   |
| `emptyTrash`     | `{ space? }`                                                          | `{ purged }`                       | `use` on space trash                      |
| `duplicate`      | `{ id, subpages?, space? }`                                           | `{ id }`                           | `view` source + `use` target              |
| `templates`      | `{ space? }`                                                          | `Template[]`                       | `view`                                    |
| `saveTemplate`   | `{ id, subpages?, space? }`                                           | `{ id }`                           | `view` source + `use`                     |
| `exportMarkdown` | `{ id, subpages?, space? }`                                           | `{ files, attachments }`           | `view`                                    |
| `importPages`    | `{ parent?, space?, pages }`                                          | `{ space, ids }`                   | `use` on space                            |
| `importContent`  | `{ items, space? }`                                                   | `{ done }`                         | `use` on imported pages                   |
| `comment`        | `{ page, body, text, anchor?, thread?, space? }`                      | `{ id }`                           | `view` on page (`comments` access)        |
| `markdown`       | `{ id, space? }`                                                      | `{ markdown }`                     | `view` on page                            |
| `backlinks`      | `{ page, space? }`                                                    | `{ linked, unlinked }`             | `view` on page (`refs.to` + `entities`)   |
| `ancestors`      | `{ id, space? }`                                                      | `{ ancestors }`                    | `view` on ancestors                       |

## 5. Collection & Document Features Required in M2b

1. **Private subtree permission inheritance**: `pages.entity.private = "private"` and `parent = "parent"` must cause `ctx.data` / `entities` / `documents` to inherit visibility from the nearest ancestor unless `private: true` overrides it; `comments.entity.parent = "page"` inherits page visibility.
2. **Soft trash & cascade tracking**: `trash: true` with `trashedWith`, `find({ trashed: true })`, `get(id, { trashed: true })`, `restore(id)`, and `purge(id)` paired with `documents.delete(null, docId)`.
3. **Reference index (`ctx.data.refs.to(uri)`)**: Automatic indexing of `links` (`refs` field) plus rich-text mentions/links inside documents so `backlinks` discovers cross-plugin references (`issue://`, `doc://`, etc.).
4. **Full-text search across titles and attached documents**: `pages.search(text)` and `entities.search(text, { schemes: ["doc"] })` returning titles and document body matches.
5. **Showable collections (`display` metadata)**: Inline `docs.database` blocks read `rookery.data.showable()` across enabled plugins, execute live `where`/`orderBy` queries, update typed fields, and delegate row/card rendering to `rookery.entities.Card` / `Row`.
6. **Collaborative document sessions & versions**: Live Yjs sync with awareness presence (`Agent` vs human), unsynced dirtiness tracking, named/auto/restore snapshots, Markdown diffing, and structural editing (`append`, `replaceBlocks`, `insert`, `edit`).
7. **Creating-agent session binding (`session` ref field)**: Pages created with `agent:session` caller contexts record `session: session://<id>` so viewers can jump back to the originating agent run.
