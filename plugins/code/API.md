# Rookery API contract for `code` (GitHub)

Every Rookery method, facility, manifest contribution, collection feature, host/client SDK surface and
cross-plugin integration this plugin uses, each marked:

- **exists in Rookery now** — implemented in `rookery/` or `@rookery/sdk` at the commit pinned in
  `crow/deps.json` (`5708f844`).
- **needed (M2)** — arrives with the plugin/extension-host/package runtime (Rookery's host halves, client
  halves served with their hashes, manifest contribution types).
- **needed (M2b)** — arrives with the datastore, spaces, documents, entities, search, schedules and webhooks.
- **needed (M5b)** — arrives with agent sessions (Parrot) and their tools.
- **stale SDK type** — the server has it, the pinned `@rookery/sdk` type does not declare it; the plugin uses
  a narrow cast (see `src/lib/sdk.ts`).

The plugin id is `code`; Rookery's own host plugin `github` (the `gh` CLI) keeps that id. The namespace, the
service and the extension point stay `github` because Projects already contributes to `github.linkPatterns`.

## 5. Known gaps and deliberate departures

- **A host half cannot create or update a connection** at the pinned SDK (`rookery.connections` lists, gets,
  resolves). The GitHub App manifest flow therefore does the conversion in the host half and hands the admin's
  browser the connection's config and credential to `connections.create`. The credential crosses the caller's
  own authenticated websocket once. When M2 adds `connections.create` to the host handle, `app.complete`
  creates it itself.
- **A connection has one sealed credential.** Rookery's `ConnectionCreate` has a single `credential` string,
  while the app type has two secrets. The plugin stores them as a JSON object in the credential
  (`{ privateKey, webhookSecret }`); a token connection stores the token itself. When M2 seals declared secret
  fields separately, `credentialValues` keeps reading the same shape.
- **No `access.levelOf` in the pinned SDK**, so notifications are not sent until the extension host exposes it:
  the alternative would be telling people about entities they cannot see.
- **Settings are default/global/user**, not per space, and `notify.send` takes Rookery's `kind`
  (`info`/`warning`/`action`) rather than the prototype's per-plugin `github.review_requested`. The three
  user settings still decide what is sent.
- **Runtime schedules** (`schedules.create`) are how a repository gets its poll interval; without them an
  attach still syncs once and webhook deliveries still apply.
- **Not ported:** the legacy `issues` collection and its conversion (`gh-issue://` aliases), because a new
  deployment has no old rows; the prototype's own Markdown renderer (Nocturne's read-only rich text is used);
  and the `github.pulls`/`github.issues`/`github.repos` commands that only open views are now `code.*`.
