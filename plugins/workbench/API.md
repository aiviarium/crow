# Workbench API contract (M3 / M5b)

Every Rookery method, stream, facility and contribution type `crow/plugins/workbench` uses, marked:

- **exists in Rookery now** — in `rookery/` today (`@rookery/sdk`, `@rookery/client`, the method table).
- **exists in #33** — `rookery#33` (`feat/cli-client`) adds it: `env.readFile`, `env.writeFile`, `env.deleteFile` and `env.connect` on hosts, `terminals.*`, the CLI's client. Names there differ from `main` (see §5).
- **needed (M2)** — the plugin system: the extension host runs host halves, plugins' client halves are served, `plugin.json` contributions are routed.
- **needed (M2b)** — the datastore, spaces, documents and entities.
- **needed (M3)** — connect: files, processes, terminals and ports on hosts through the server.
- **needed (M5b)** — Crow's plugins on the datastore and plugin system. Workbench has no collections; M5b is where the API it calls is exercised end to end.

Files and git both run against a **host**, addressed `env://NAME`. Levels are `view` ⊂ `use` ⊂ `manage` on `env://NAME`, or the org role `admin` (`plans/design.md`, "Levels on a host"). Everything the workbench does needs `use`; a `view` holder can open the editor read-only where the server allows reads.

Files use the base64 file methods, not `env.exec`, so a large save does not travel through a shell command. A save names the version it read (`ifMatch`/`sha256`); a mismatch is `CONFLICT` with `details.current`, and the workbench opens its save-conflict tab. `#33` renames `env` to `host` in the file types and `ifMatch` to `etag`; one function in `src/api.ts` (`writeFile`) and the `env` parameter names change with it.

## 5. What the workbench does not use, and why

| Thing                                                       | Why not                                                                                                                                                                                                                 |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entities.register` (prototype)                             | Rookery has no client-side entity registration; the entity URI is built in `src/api.ts` and the server's entity router is **needed (M2b)**                                                                              |
| the prototype's `crow.drafts`                               | Rookery's `storage` at `scope: "user"` holds drafts (`draft:ws:<env>:<root>`)                                                                                                                                           |
| the prototype's `crow.env.portUrl`                          | no client helper at this pin; the URL is `/env/<name>/port/<n>/`, the proxy **needed (M3)**                                                                                                                             |
| the prototype's `runProcess` stream (`env.process`)         | not in the method table yet; search and sync use `env.exec` (**needed (M3)** for streaming and cancel)                                                                                                                  |
| `env.stat`                                                  | not in the SDK or the #33 types; a file's size comes with `env.readFile`, so the large-file check happens after the read (the server caps host file reads at 4 MiB for provider environments)                           |
| `env.deleteFile` with `recursive`                           | the method deletes one file; folders are removed with `env.exec ["rm","-rf"]` inside the host's roots                                                                                                                   |
| the TypeScript language service                             | the workbench has no project to resolve imports against; TS/JS are highlighted by Monaco's Monarch grammar, and the TypeScript worker (≈10 MB of compiler) is left out to keep the shell's build within memory and time |
| the prototype's `Environment` trait, its provider and berth | removed by the plan; hosts are Rookery's                                                                                                                                                                                |

## 6. Build and runtime

- Monaco is dynamically imported from `src/monaco/index.ts`; Vite puts it (and the JSON/CSS/HTML workers) in chunks that load with the first workbench view. The shell's entry stays at its previous size, and the build grows by about 3.5 MB of script (≈900 kB gzipped) plus ≈140 kB of CSS.
- `bun run build` on the shell takes about 18 s here with Monaco (7 s without it), under Node's default 2 GB heap. Importing all of `monaco-editor` instead (every language, every feature, the TypeScript worker) fails the build with an out-of-memory error at that heap.
- `env.exec` is unary, so search results appear when the command ends and a push's progress is not shown. `env.process` (M3) is what makes both streaming.
- File reads and writes travel as base64; a 5 MiB default threshold (`workbench.largeFileBytes`) keeps the editor from loading a large file unless asked.
